# Forensic Report: Agent-1 V2 Data Persistence Failure

**Date:** 2026-01-30
**Investigator:** Principal Backend Engineer (Agent)
**Subject:** Persistent NULL/Empty V2 Data (Dimensional Scores) in Database

## 1. Executive Summary
The data loss is caused by a **critical regression in the V1 fallback path** within `core/pipelines/ingestion.py`.
The system is executing a **"Hybrid V1" agent** (a V1 file modified with partial V2 logic) rather than the "Strict V2" agent I implemented. My V2 Adapter correctly identifies this as "Not Strict V2" and routes to the V1 persistence logic. However, during the implementation of the V2 Adapter, I inadvertently **removed the legacy code** that extracted `dimensional_scores` from this Hybrid V1 output. Consequently, valid scoring data generated by the Hybrid agent is discarded before persistence.

## 2. Verified Execution Paths
The user execution follows "Path B" (Ingestion), which differs from "Path A" (Pipeline Runner).

*   **Path A: Pipeline Runner (`/pipeline/start`)** -> Uses `version_router` -> Calls `v2/agent1_voice.py` (Strict V2). **(Adapter Works Here)**
*   **Path B: Ingestion (`/ingest`)** -> Hardcoded import of `v1/agent1_voice.py` -> Calls Hybrid V1 Agent. **(Adapter Fail & Regression Here)**

## 3. Data Flow Trace (The "Hybrid" Problem)

### Step 1: Agent Execution (Hybrid V1)
-   **Code:** `core/agents/v1/agent1_voice.py` (Lines 43-160) calls `DimensionalScorer`.
-   **Output Payload:**
    ```json
    {
      "raw_json": {
        "explicit_rules": {...},
        "dimensional_scores": {...},  <-- Present inside raw_json
        "version": 2
      },
      "summary": {
        "dimensional_scores": {...}   <-- Present inside summary
      }
    }
    ```
-   **Critical Note:** It does **NOT** contain `refined_explicit_rules` (the signature of Strict V2).

### Step 2: Ingestion Adapter (My Fix)
-   **Code:** `core/pipelines/ingestion.py`
-   **Check:** `if "refined_explicit_rules" in agent1_result:`
-   **Result:** `False` (Hybrid agent lacks this key).
-   **Action:** Branch to `else` (V1 Legacy Path).

### Step 3: V1 Legacy Path (The Regression)
-   **Original Code:** Checked `output['summary']['dimensional_scores']` and added it to profile.
-   **Current Code (My Fix):**
    ```python
    else:
        profile_data = {
            # ... standard V1 mapping ...
            # MISSING: Logic to extract dimensional_scores from summary!
        }
    ```
-   **Result:** `profile_data["dimensional_scores"]` is missing.

### Step 4: Persistence
-   **Code:** `VoiceProfilesRepo.save_profile`
-   **Input:** `dimensional_scores = profile_data.get('dimensional_scores')` -> `None`.
-   **SQL:** `INSERT INTO voice_profiles_machine (..., NULL, ...)`
-   **DB State:** Rows exist (because `version=2` is passed), but scores are NULL.

## 4. Adapter Effectiveness Check
| Check | Status | Reason |
| :--- | :--- | :--- |
| **Strict V2 Detection** | **CORRECT** | Correctly identifies that Hybrid V1 is NOT Strict V2. |
| **V2 Mapping** | **Skipped** | Branch logic sends execution to V1 `else` block. |
| **V1 Fallback** | **BROKEN** | Legacy logic to handle "Hybrid V1" features was deleted. |

## 5. Most Likely Root Cause
**Rank 1 (Confirmed):** Regression in `core/pipelines/ingestion.py`. I removed the legacy handling for `dimensional_scores` in the `else` block while focusing on the V2 strict adapter. The test environment runs the Hybrid V1 agent, so it hits this regression.

## 6. Why Previous Fixes Did Not Resolve the Issue
My previous fixes assumed the system was running the **Strict V2 Agent** (`core/agents/v2/agent1_voice.py`). I added a robust adapter for that specific output schema. However, because `ingestion.py` hardcodes the V1 import, the system never generates the "Strict V2" output (with `refined_explicit_rules`), so my fixed code is never entered. It falls back to the V1 path which I accidentally stripped of its partial V2 support.
